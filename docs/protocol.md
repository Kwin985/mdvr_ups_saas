# 协议实现说明

> 依据 `docs/UPS串口通讯协议（RS485）v1.4.doc`（思拓内部协议）整理，代码常量集中在
> `src/protocol/frame.rs` 与 `src/protocol/codec.rs`。**命令字是 ASCII 字母**，不是二进制码。

## 1. 物理层

| 项目 | 值 |
| --- | --- |
| 接口 | RS485 |
| 默认串口参数 | 9600 bps、8 数据位、无校验、1 停止位（8-N-1） |
| 发送间隔 | 两次数据发送间隔 **不小于 10ms**（上下行都适用） |

MDVR 只做透传：串口字节原样进 TCP，平台侧负责组帧与解析。

## 2. 帧格式

```text
0x7E | 设备类型 | 地址码 | 命令字 | 数据正文 ... | 校验码 | 0x7E
      1B        1B      1B       nB            1B      1B
```

- **设备类型**：`0x01` 多功能手麦、`0x02` LED 面板、`0x10` UPS。
- **地址码**：RS485 设备有效且可配置，范围 `0-247`；其他默认 `0x00`。
- **命令字**：ASCII 字母，见第 3、4 节。
- **校验码**：校验位之前所有数据的异或值。
- **结尾符**：`0x7E`。

### 转义

| 原始字节 | 线上字节 |
| --- | --- |
| `0x7E` | `0x7D 0x02` |
| `0x7D` | `0x7D 0x01` |

只对两个 `0x7E` 之间的内容转义，**只解码一次**（编码一次后不能再把 `0x7D` 当 `0x7E` 再转一次）。
文档示例：

```text
原始数据:   'u' 0x03 0x7D 0x15 0x7E
封装后:     0x7E 'u' 0x03 0x7D 0x01 0x15 0x7D 0x02 0x1E 0x7E
```

### 校验口径：文档与实机不一致

文档示例的 `0x1E` 是**包含开始符 `0x7E`** 算出来的；而现场抓到的 `a` 帧：

```text
7E 10 00 61 03 EF 05 19 10 68 10 00 20×20 E9 7E
```

- 含开始符：`0x97`（与帧内 `0xE9` 不符）
- 不含开始符（`0x10` 起算到数据正文末字节）：`0xE9` ✅

**实现以实机为准**：`Frame::checksum()` 只异或 `设备类型 ^ 地址码 ^ 命令字 ^ 数据正文`，
`Frame::decode_body` 用同一口径校验，坏帧按 `ChecksumMismatch` 丢弃。

### 解析策略（`FrameParser`）

1. 扫描起始 `0x7E`，丢弃前导垃圾并计入 `discarded_bytes`；
2. 找下一个 `0x7E` 作为帧尾（载荷中的 `0x7E` 已转义，不会误判）；
3. 反转义 → 校验 → 产出 `Frame`；
4. 坏帧只丢帧体，帧尾 `0x7E` 留在缓冲里作为下一次同步起点；
5. 缓冲超过 1024 字节仍无帧尾时丢弃帧头，防止内存无界增长。

## 3. UPS → 主机

| 命令字 | 含义 | 数据正文 |
| --- | --- | --- |
| `'a'` `0x61` | 实时状态信息 | 28 字节，见下 |
| `'V'` `0x56` | 版本信息 | 7 字节 ASCII，如 `V010101` |
| `'b'` `0x62` | 串口参数设置应答 | 1 字节 ack |
| `'d'` `0x64` | 地址码设置应答 | 1 字节 ack |
| `'f'` `0x66` | 推送频率设置应答 | 1 字节 ack |
| `'N'` `0x4E` | SN 设置应答 | 1 字节 ack |
| `'S'` `0x53` | 开始升级应答 | 1 字节 ack |
| `'D'` `0x44` | 升级数据应答 | `FrameID(2B 大端) + ack` |
| `'F'` `0x46` | 结束升级应答 | 1 字节 ack |

`ack`：`0x30` 成功、`0x31` 校验错（要求重发当前记录）、`0x32` 校验正确但写 Flash 失败（须整轮重来）。

### `'a'` 实时状态信息

```text
0x7E type addr 'a' PWRH PWRL VOLH VOLL TEMH TEML BLEVEL SMART SN(20B) sum 0x7E
```

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| PWRH/PWRL | 2B 大端 | 电源电压采样值 |
| VOLH/VOLL | 2B 大端 | UPS 电压采样值 |
| TEMH/TEML | 2B 大端 | 当前温度（摄氏度）采样值 |
| BLEVEL | 1B | 剩余电量 `0-100`（%） |
| SMART | 1B | 健康状态：0 良好 / 1 一般 / 2 差 / 3 差（建议更换） |
| SN | 20B | UPS 唯一识别码（ASCII），未写入时为 20 个 `0x20` |

采样值单位文档未标注，按现场惯例取 **0.01 倍率**（`原始值 / 100`）：

| 字段 | 抓包原始值 | 换算 |
| --- | --- | --- |
| PWR | `0x03EF` = 1007 | 10.07 V |
| VOL | `0x0519` = 1305 | 13.05 V（12V 系统充电电压） |
| TEM | `0x1068` = 4200 | 42.00 ℃ |
| BLEVEL | `0x10` = 16 | 16 % |
| SMART | `0x00` | 良好 |
| SN | 20×`0x20` | 未写入 |

实现：`codec::StatusA::parse/encode`，倍率常量 `STATUS_A_DIVISOR = 100.0`；
温度按 `i16` 解释以支持零下。

### `'V'` 版本信息

命令字 `V`，数据正文为 **ASCII 版本字符串**。文档示例 `V010101` 是 7 字节，
按「V + 3 组两位数字」读作 MCU 版本 **1.1.1**。

> **实机差异**：现场设备（`UPS-192.168.1.169`）返回 **9 字节** `V26052602`，
> 并非 7 字节。因此平台**不假设固定长度**，只取可打印 ASCII 正文原样存库
> （`codec::Version::raw_string`），避免截断或格式不符时整段丢失。

平台收到后写入 `devices.firmware_version`，在设备面板「固件版本」、监控树
`/api/tree` 与分析导出 CSV 的 `firmware` 列展示。

## 4. 主机 → UPS

| 命令字 | 含义 | 数据正文 |
| --- | --- | --- |
| `'r'` `0x72` | 请求版本信息 | 空 |
| `'u'` `0x75` | 重启系统 | 空（**实机有应答** `0x30`，见下） |
| `'b'` `0x62` | 串口参数设置 | `para` 2B 大端（**本平台已禁用**，见下） |
| `'d'` `0x64` | 设备地址设置 | 1B 地址 `0-247` |
| `'f'` `0x66` | 数据推送频率 | 2B 大端，秒，`1-3600`（默认 60s） |
| `'N'` `0x4E` | SN 设置 | 20B ASCII |
| `'S'` `0x53` | 开始升级 | `Size(2B) + Number(2B)`，大端 |
| `'D'` `0x44` | 升级数据 | `FrameID(2B) + 数据包`，大端 |
| `'F'` `0x46` | 结束升级 | 空 |

### `'u'` 实机有应答

文档写的是"空（无应答）"，但现场设备 `UPS-192.168.1.169` 实测会回一帧应答，正文 `0x30`
（成功）。平台按"等待应答"处理：收到就展示「应答：成功 (0x30)」，5 秒内没收到就提示
"发送超时"。两种情况都不影响设备重启本身，超时只是链路/设备没回，不代表命令没生效。

### `'b'` 为什么平台禁用

MDVR 是透传链路，**不跟随** UPS 的波特率变化：UPS 被改成 19200 后，MDVR 仍按原波特率
转发，链路立即断开，设备从平台掉线，只能到现场用串口工具救回来。所以该功能保留入口但
不可用——前端灰化并给出提示，后端同样拒绝（`cmd.err_baud_disabled`），防止手搓请求绕过。
后续要做的话，得先让 MDVR 侧同步切波特率（或让 UPS 在应答里回带确认后再延迟生效）。

### `'b'` 的 `para` 位域（2 字节大端）

| 位 | 含义 |
| --- | --- |
| bit0-3 | 波特率档位：0:600、1:1200、2:2400、3:4800、4:9600、5:19200、6:38400、7:57600、8:115200、9:28800 |
| bit4-6 | 校验格式：000 none、001 odd、011 even、100 mark、000 space |
| bit7 | `1` 两位停止位、`0` 一位停止位 |
| bit8-15 | 保留 |

实现：`codec::baud_para(index)`、`codec::baud_name(index)`、`codec::interval_para(secs)`。

### 地址码：下发必须用设备当前地址

`'d'` 改址后，设备改用**新地址**收发，旧地址不再响应。平台因此：

- **下发**（`r`/`u`/`b`/`d`/`f`/`N`、OTA 的 `S`/`D`/`F`）一律使用库里的
  `devices.address`，不再写死 `0`；
- **学习**：设备上行 `'a'` 帧的地址字节就是它当前的地址，地址变化时自动回写
  `devices.address`（设备重连后即使库里是旧值也能自愈）；
- **改址**：`'d'` 帧头仍用**旧地址**发送（设备此时还在旧地址上），载荷是新地址；
  发送成功后平台立即记住新地址。
- 设备重连不会把 `address`/`baudrate`/`report_interval` 重置为默认值——这三项是
  设备侧配置，只在新设备首次入库时写默认值。

## 5. OTA（ISP 升级）

> **当前已停用**：`src/ota/mod.rs` 的 `OTA_ENABLED = false`。页面入口置灰、后端
> `/ota/start` 与 `/ota/{sn}/start` 直接拒绝，不创建 job、不触碰设备。固件上传到库
> 不触碰设备，仍开放；历史任务与固件库照常可查。
> 启用条件见 `OTA_ENABLED` 的文档注释，并有编译期断言 `const _: () = assert!(!OTA_ENABLED)`
> 兜底——改成 `true` 会直接编译失败，必须 consciously 处理。
> 停用原因：OTA 全流程尚未在真机上完整跑通过一次，且 `S` 的载荷形式与 MDVR 参考实现
> 互相矛盾（见第 9 节）。

```text
平台                                   UPS
 │  S  Size Number                      │
 │─────────────────────────────────────>│
 │<─────────────────────────────────────│ S + ack(0x30)
 │  D  FrameID 64B                      │
 │─────────────────────────────────────>│
 │<─────────────────────────────────────│ D + FrameID + ack
 │  ...                                 │
 │  F                                   │
 │─────────────────────────────────────>│
 │<─────────────────────────────────────│ F + ack(0x30)
```

- **开始**：3 秒内每 100ms 重发 `S`，收到 `0x30` 才开始发数据；`0x31` 表示 MCU 没准备好，继续请求。
- **数据**：每包 64 字节，最后一包按实际长度；逐包等待应答。
  - `0x30`：下一包；
  - `0x31`：重发当前包，连发 3 次都错则退出（实现按 `UPS_OTA_MAX_RETRIES` 计）；
  - `0x32`：Flash 写入失败，**从 `S` 整轮重来**，3 次失败则退出；
  - 超时：等同 `0x31` 处理。
- **结束**：发 `F`，`0x30` 判定成功；`0x31` 重发 `F`（最多 3 次）；`0x32` 需整轮重来。
  结束帧超时按 `ota_end_timeout_ms`（默认 **5000ms**）计——`F` 会让设备校验整包并写
  Flash，比数据包慢得多，MDVR 参考实现同样给 5s。
- **数据包应答按 `FrameID` 核对**：只认当前包的应答，上一包的迟到/重复帧直接丢弃，
  不当成确认。4G 链路会丢包重传，来者不拒会静默跳过一个数据包。
- **隔离**：升级期间设备 `busy=true`，接入层拒绝普通下行；OTA 自身以 `force=true` 绕过。
- **中止**：设备断线时 `on_device_offline` 让状态机在下一个检查点退出并标记 `aborted`。
- **节流**：所有下行经写任务串行发送，相邻帧间隔 ≥ `UPS_DOWNLINK_GAP_MS`（默认 10ms）。
- **大小上限**：`Size` 为 2 字节，升级包最大 **64 KiB**（`codec::OTA_MAX_SIZE`）。

## 6. 平台自定义：注册握手（可选）

串口协议没有注册命令，这是 MDVR 与平台之间的 TCP 约定，支持三种形式：

```text
{"mdvr_id":"MDVR-001","ups_sn":"UPS-9001"}\n
MDVR-001|UPS-9001\n
二进制帧：cmd=0x80，载荷 "MDVR-001|UPS-9001"
```

平台绑定连接与 SN 后回一条 `cmd=0x80, payload="OK"`（设备可忽略），随后进入纯字节流透传。

**注册是可选的**：多数真实 MDVR（含 4G 透传模块）只会把串口字节原样转发，
不会发上面的注册行。平台连接后只做一次有限窗口探测（默认 1.5s，`UPS_REG_PROBE_MS`）：
窗口内出现合法注册就按注册身份上线；没出现、先收到业务帧或窗口超时，都按
**回退身份** `MDVR-<IP>` / `UPS-<IP>` 直接放行，绝不因此断开。之后设备在 `a` 帧里
上报真实 SN 时，平台自动完成重绑（设备行与历史样本整体迁移到真实 SN），
重绑失败（如目标 SN 被其他连接占用）则保持占位身份并在日志提示。

## 8. 与真实设备联调时的检查项

1. 采样值倍率（现按 0.01）是否与实机一致，只需改 `STATUS_A_DIVISOR`；
2. 温度是否需要 `i16`（零下场景）；
3. 设备地址是否已配置（未配置为 `0x00`，平台下行同样用 `0x00`）；
4. 校验是否真的排除开始符（本文按实机口径，若换批次设备需重测）。

## 9. 与 MDVR 参考实现（`Serial_Ups.cpp`）的差异

MDVR 侧的 UPS 串口驱动（`CBB/Serial/SerialDevice/Serial_Ups.cpp`）是同一套 UPS
协议的另一个实现，两者逐条比对后结论如下。

### 参考实现与协议文档/实机抓包矛盾，平台**没有**照抄

| 项 | MDVR 参考实现 | 平台 | 依据 |
| --- | --- | --- | --- |
| 转义范围 | 把首尾 `0x7E` 也转义，实际发出 `7D 02 … 7D 02` | 只转义两个 `0x7E` 之间的载荷 | 实机抓包 + 平台下行 `7E 10 00 72 62 7E` 能被设备正常应答。且参考实现自己的接收解析按字面 `0x7E` 找帧，发出去的帧它自己都解不了 |
| `S` 载荷 | 1 字节 `'S'` | `Size(2B) + Number(2B)` | 协议文档 3.4 节 |
| `D` 载荷 | 裸数据，无 `FrameID` | `FrameID(2B) + 数据包` | 协议文档 3.4 节 |
| `F` 载荷 | 1 字节 `'F'` | 空 | 协议文档 3.4 节 |
| `D` 应答解析 | 取载荷第 2 字节当 ack | `FrameID(2B) + ack`，取第 3 字节 | 若应答真带 `FrameID`，参考实现读到的是 `FrameID` 高字节（通常 `0x00`），永远匹配不上 `0x30` |
| 应答帧校验 | 升级应答路径不校验帧头帧尾、不校验校验和 | 全链路校验 | 平台 `FrameParser` 统一处理 |

> 这些差异建议与 UPS 固件方确认一次。若真机 OTA 首轮就卡在「等待设备应答 S 命令」，
> 优先按上表核对 `S` 的载荷形式。

### 参考实现有问题、平台已规避或更好的点

| 项 | MDVR 参考实现 | 平台 |
| --- | --- | --- |
| 接收缓冲溢出 | 超过 256 字节直接整体复位 | 1024 字节才丢弃帧头，坏帧只丢帧体 |
| 文件大小 | `int`，无上限（`Size` 只有 2 字节，超 64 KiB 会截断） | 明确拒绝超 64 KiB |
| 断线中止 | 无 | 设备掉线即取消并标记 `aborted` |
| 进度口径 | 已发送字节 / 总大小 | 已**确认**包 / 总包 |
| 下行节流 | 硬编码 10ms | `downlink_gap_ms` 可配（默认同为 10ms） |

### 参考实现有价值、平台本轮吸收的点

1. **`D` 应答按 `FrameID` 核对**（`wait_ack(expect)`）：丢弃不匹配的迟到/重复应答；
2. **`F` 的 `0x32` 走整轮重来**，而不是把已传完的任务直接判失败；
3. **`F` 超时放宽到 5s**（原 3s 偏紧），并做成可配项 `ota_end_timeout_ms`；
4. **`S` 阶段的 `0x32` 改为继续重试 `S`**（原为直接失败）：此阶段一个字节都没发，
   「整轮重来」没有意义，由 `ota_begin_window_ms` 窗口兜底。
