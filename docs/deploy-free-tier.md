# 部署评估：免费/试用云服务器（Google 申请不下来时的备选）

> 起因：Google Cloud Always Free 因银行卡不符合要求申请不了。本文按**本程序的真实约束**
> 重新筛一遍，不是泛泛的"免费 VPS 大全"。
>
> 硬件/流量数字沿用 [`deploy-e2-micro.md`](deploy-e2-micro.md) 的实测结果，与选哪家无关。

## 1. 先看硬约束——它筛掉了大多数"免费"

本程序不是普通 Web 应用，它是**一个常驻进程 + 两个入站 TCP 端口**：

| 端口 | 用途 | 谁能连 |
| --- | --- | --- |
| `1688` | 透传接入，MDVR 4G 模块**主动外连**进来 | 任意公网 IP |
| `18080` | Web 控制台 | 浏览器 |

关键推论：

1. **必须有一个公网 IP，且两个端口都能从外面连进来。** MDVR 是外连方，
   所以平台侧不需要特殊网络配置，但**端口必须是公网可达的任意 TCP 端口**，
   不能是"只给 80/443 的 HTTP 反向代理"。
2. **必须常驻。** 免费 tier 里"闲置就休眠、冷启动 30 秒"的那类（Render 免费档等）
   直接出局——设备重连窗口等不起。
3. **必须有持久磁盘。** DuckDB 是嵌入式数据库，库文件就在本地，
   容器重建即丢数据。

按这三条过一遍，结论很窄：**要的是免费虚拟机（VPS），不是免费 PaaS。**

## 3. Oracle Cloud Always Free：规格最好，但两个坑

官方文档（2026-06 版）口径：

- **AMD 微型实例** ×2（`VM.Standard.E2.1.Micro`，1 OCPU / 1 GB）
- **Arm Ampere A1** 折合 **2 OCPU + 12 GB**（1500 OCPU 小时 + 9000 GB 小时/月）
- 块存储 **200 GB**、出站流量 **10 TB/月**
- Always Free **不过期**；另送 $300 试用金（30 天）

按本程序实测换算（1000 台 / 30s 上报：0.078 核、58.5 MB RSS、51.8 KB/台/天）：

| 资源 | Oracle 免费档 | 本程序需要 | 余量 |
| --- | --- | --- | --- |
| CPU | 2 OCPU（A1） | 0.078 核 @1000 台 | ~25 倍 |
| 内存 | 12 GB（A1）/ 1 GB（AMD） | 58.5 MB @1000 台 | 极充裕 |
| 磁盘 | 200 GB | 9.1 MB/台/180天 | ~2.2 万台 |
| 出站 | 10 TB/月 | 169 MB/月（开 brotli） | 极充裕 |

### 坑一：闲置回收（对我们这种负载特别致命）

Oracle 官方原文：*Idle compute instances may be reclaimed by Oracle if, over a 7-day
period, CPU, network, and (for A1 shapes) memory utilization are all below 20% at the
95th percentile.*

翻译一下：**7 天里 95% 的时间 CPU 都低于 20% 就可能被回收。**

而我们这个平台的设计目标就是"尽量空闲"——1000 台设备时 CPU 占用约 4%（0.078/2），
网络流量一个月 169 MB。这正好是回收策略的头号目标。真要上 Oracle，得常驻一个
占 25% 左右 CPU 的保活进程，很讽刺但必要。另外回收执行并不严格，属于"可能"。

### 坑二：注册要外币实体信用卡

Oracle 注册要做 **1 美元预授权**验证，且明确要求支持外币的实体 Master/VISA；
虚拟卡、信息不一致会直接失败甚至封号。**国内发行的银联单币卡基本过不了**——
这和 Google Cloud 失败的原因是同一个，所以如果你的卡在 Google 被拒，
Oracle 大概率同样被拒。值得一试的组合：招行/中行等双币种全币卡 + 手机热点网络
（家庭宽带 IP 被风控也是常见失败原因）。

### 其他注意

- **主区域（Home Region）选定后不可改**，且 Always Free 资源只能开在主区域。
  选离国内近的（日本/韩国/新加坡）延迟更低，但韩国春川域不支持 A1。
- Arm 实例在热门区域常年 "out of host capacity"，要反复重试或换可用域。
- 试用期结束前，A1 实例总和不能超过 2 OCPU / 12 GB，否则 30 天后被删。

## 4. 国内云试用：对你最现实的路

不需要外币卡，实名认证（身份证 + 支付宝）即可，公网 IP 全端口开放，
且机房在国内、4G 链路延迟低。

| 厂商 | 权益 | 说明 |
| --- | --- | --- |
| **阿里云** | 个人新用户 ECS 免费试用**最长 3 个月** | 额度制，选低配能撑满 3 个月；入口 <https://free.aliyun.com> |
| **腾讯云** | CVM 蜂驰型 4 核 8G / 5M 带宽，免费 7 天 | 配置最慷慨但时间短，适合压测 |
| 华为云 | Flexus L 实例试用 | 备选 |

建议走**轻量应用服务器（Lighthouse）**而不是 ECS：更便宜、自带防火墙面板、
开箱即用，本程序这种单进程场景完全够。

### 4.1 推荐规格（阿里云，照着选即可）

> 本程序资源占用极低（实测 1000 台才 0.078 核 / 58.5 MB / 1.5 GB 月流量），
> 所以**选最小档就绰绰有余**，把钱花在"省心"而不是"配置高"上。

| 项 | 推荐值 | 说明 |
| --- | --- | --- |
| 产品 | 轻量应用服务器 Lighthouse（长期）／ ECS 经济型 e（走 300 元试用额度） | 轻量自带防火墙面板、开箱即用 |
| vCPU | **2 核**（1 核也够） | 留余量，价格差极小 |
| 内存 | **2 GB**（1 GB 也可） | 按 §5 设 `UPS_DB_MEMORY_LIMIT_MB=256` + `UPS_DB_THREADS=1` 即可 |
| 系统盘 | **40 GB ESSD**（20 GB 都富余） | 数据量极小（9.1 MB/台/180 天），别买大 |
| 带宽 | **3 Mbps 固定** 或 **按使用流量（峰值 3–5 Mbps）** | 月流量 KB 级，怎么选都便宜 |
| 镜像 | **Ubuntu 22.04 LTS 64 位** | DuckDB bundled 编译最省心；Alibaba Cloud Linux 3 亦可 |
| 地域 | 华东1（杭州）/ 华南1（深圳）/ 华东2（上海） | 离 4G 出口近、延迟低 |
| 公网 IP | **自动分配 IPv4（必须）** | MDVR 要主动外连进来 |
| 操作系统 | **Linux**（FreeBSD 不行见 §7；Windows 也行但 Linux 更省） | —— |

**安全组 / 防火墙（关键）：**
- `1688/tcp`：放行，建议**限制来源 IP**（只放 MDVR 出口网段），它是裸 TCP 零认证；
- `18080/tcp`：只放行你自己的办公 IP，或监听 `127.0.0.1` + Caddy/Nginx 反代上 HTTPS
  （`18080` 是 HTTP+JWT， plaintext 令牌别直接公网暴露）。

**申请步骤：**
1. 打开 <https://free.aliyun.com>，用支付宝/钉钉登录，完成实名认证（身份证）；
2. 免费试用里选"云服务器 ECS 经济型 e"或"突发性能 t6"，按上表规格选；
   （或走轻量：<https://swas.console.aliyun.com> 新建实例，选同规格镜像）；
3. 创建时勾选"分配公网 IPv4"，带宽选 3 Mbps 固定或按流量；
4. 安全组放行 `1688`、`18080`（TCP）；
5. SSH 登录后：装 Rust 工具链 → 打开 DuckDB bundled 编译（约 10 分钟，见 §5 第 1 条）
   → 放二进制、配 env、起服务。

### 4.2 实际开出实例核对（2026-10-26）

用户已创建实例，规格如下：

| 项 | 实际值 | 是否满足 |
| --- | --- | --- |
| 规格 | `ecs.e-c1m1.large`（经济型 e） | ✅ 2 核完全够 |
| CPU / 内存 | 2 核 / 2 GB | ✅ 远超需求 |
| 镜像 | Ubuntu 26.04 64 位（`ubuntu_26_04_..._20G_alibase_...vhd`） | ✅ Linux，DuckDB 可编译 |
| 系统盘 | 20 GB | ✅ 数据量极小；编译 DuckDB 需临时空间，见下 |
| 网络 | VPC `vpc-bp1kbom9dr49339kefm4r` + 交换机 `vsw-bp1n8r25tc5krrgp24rk9` | ⚠️ 见下"缺公网 IP" |

**结论：计算/系统规格满足。但有三处必须补齐，否则程序跑不起来：**

1. **缺公网 IP（最致命）。** 清单里没有弹性公网 IP（EIP）——VPC 内的 ECS 默认**只有私网地址**，
   MDVR 和浏览器都连不进来。必须在控制台"弹性公网 IP"里申请并绑定到这台实例，
   带宽选 3 Mbps 固定或按流量。
2. **安全组入站规则。** 默认安全组通常只放 22(SSH)。需手动加 `1688/tcp`（建议限制来源 IP）
   和 `18080/tcp`。
3. **20 GB 盘 + 2 GB 内存编译 DuckDB bundled 偏紧。** 链接阶段 DuckDB 静态库很吃内存，2 GB 易 OOM。
   两条路二选一：① 本机开 4 GB swap 再 `--features duckdb/bundled` 编译；
   ② 在配置更高的机器上编好 `x86_64-unknown-linux-gnu` release 二进制，直接 scp 上去
   （Rust 二进制基本静态，拷过去就能跑）。

## 5. 上云前必须做的三件事（现在还没做）

1. **Linux 构建从没跑过。** 当前 `run-prod.sh` 写死 `mdvr_ups.exe`，也没有 CI。
   DuckDB 依赖是 git 依赖且 `default-features = false`（不启用 `bundled`），
   Windows 上靠 `DUCKDB_LIB_DIR` 指向预编译库；Linux 上要么同样预编译 libduckdb，
   要么打开 `bundled` 现场编译（约 10 分钟）。这是第一个要解决的工程问题。
2. **安全。** `18080` 是 HTTP + JWT，直接暴露在公网等于明文传输管理员令牌。
   至少：套一层 Caddy/Nginx 反代上 HTTPS，`18080` 只监听 `127.0.0.1`；
   `1688` 必须保持公网开放，建议在防火网上限来源。
3. **数据与密钥。** `UPS_DB_PATH` 指到数据盘；`UPS_JWT_SECRET` / `UPS_ADMIN_PASSWORD`
   用随机值（`openssl rand -hex 32`），别沿用默认。`UPS_DB_THREADS=1`、
   `UPS_DB_MEMORY_LIMIT_MB=256` 在小内存机器上是必须的，否则一次大范围聚合查询
   就能把进程撑爆（详见 e2-micro 文档第 4.1 节）。

## 6. 建议路线

1. **先申请阿里云 3 个月试用**（不要外币卡，最可能成功），按上面 §5 准备好 Linux 构建；
2. 试用期内把 `1688`/`18080` 打通，用一台真实 MDVR 跑 72 小时观察重连与掉线；
3. 顺手把 OTA 在真机上验证掉（`OTA_ENABLED` 目前是关的）——上云和真机 OTA
   验证可以并行，互不阻塞；
4. 试用结束转轻量应用服务器按量付费，年成本可忽略；
5. Oracle 作为"想再省一点"的备选，但先解决外币卡和闲置回收两个问题。

## 7. Serv00（FreeBSD 免费虚拟主机）：资源够，但卡在 DuckDB

Serv00 是波兰的免费虚拟主机，**跑的是 FreeBSD 而不是 Linux**。规格（2024–2026 各来源一致）：

- 存储 3 GB、流量**无限**、TCP/UDP 端口 **3 个**、系统进程 **20 个**、RAM **512 MB**
- 账号有效期 10 年，但**超过 90 天不登录 Panel + SSH 会被删号**（需自动登录脚本保号）
- 支持 SSH、面板里开 "Run your own applications"、Port reservation 保留端口
- 机房在**欧盟**

### 资源/端口层面：其实都够

| 需求 | Serv00 提供 | 结论 |
| --- | --- | --- |
| 2 个公网 TCP 端口（1688/18080） | 3 个可保留端口 | ✅ 程序端口可配（`UPS_WEB_ADDR` / `UPS_INGEST_ADDR`），映射到保留端口即可 |
| 常驻进程 | 20 进程额度，程序只占 1 个 | ✅ |
| 持久磁盘 | 3 GB | ✅（DuckDB 库文件在本地） |
| 内存 | 512 MB | ✅（实测 1000 台才 58.5 MB，小规模更宽松） |
| 不要外币卡 | —— | ✅ 比 Oracle 强 |

### 致命点：FreeBSD + DuckDB 硬依赖

1. **DuckDB 是本程序的无条件依赖。** 它在 `Cargo.toml` 的 `[dependencies]` 里，
   没有任何 feature gate；`src/storage/mod.rs` 直接 `use duckdb::Connection`。
   不是"可关掉的可选功能"，关不掉。
2. DuckDB 本质是 **C++ 引擎**。在 FreeBSD 上构建，要么用 FreeBSD 工具链现场编译它的
   C++，要么链接一个 FreeBSD 预编译的 `libduckdb`。而 DuckDB 官方**不发布 FreeBSD
   预编译包**；从 Linux/macOS 交叉编译 DuckDB C++ 到 FreeBSD 基本不可行
   （需要 FreeBSD sysroot + clang freebsd target，Serv00 也不给 root 和构建工具链
   让你在那上面编）。
3. FreeBSD 自带 Linuxulator（跑 Linux 二进制），但共享主机**通常不对用户开放**这一内核特性。

### 结论

**当前程序不能直接跑在 Serv00 上。** 比 Oracle 还硬——Oracle 的外币卡至少还能试，
这里是结构性不兼容。要让它跑起来，只有两条路，都是工程改造：

- **(A) 把 DuckDB 改成可关闭**，用替代存储（SQLite / 纯文件）做后端。这是一项不小的重构，
  要新增 `no-duckdb` 之类的 feature 并把 `storage` 抽象掉。
- **(B) 找一台 FreeBSD 机器**（哪怕临时开一台）把 DuckDB 编进静态二进制，再把成品
   `x86_64-unknown-freebsd` 二进制丢上去跑。Serv00 本身没法完成这一步。

即便过了 DuckDB 这一关，Serv00 还有两个运维包袱：90 天自动登录保号、进程保活
（cron 或循环脚本，因为没有 systemd、也不是 root），再加上欧盟到国内 4G 链路的延迟。
**综合看，它不如国内云试用（§4）现实**——后者 Linux + 全端口 + 机房在国内，
只差"免费时长有限"这一条，而本程序长期跑的成本本就可忽略（§4 末）。
